# 便利機能・チートシート

## .gitignore — 管理対象外にする

バージョン管理に含めたくないファイルを指定できます。
リポジトリのルートに `.gitignore` というファイルを作成します。

```title=".gitignore"
# ログファイル
*.log

# OS固有のファイル
.DS_Store
Thumbs.db

# 一時ファイル
*.tmp
*.bak

# 機密情報
.env
credentials.json
```

!!! tip "何を.gitignoreに入れるべき？"
    - 自動生成されるファイル（ログ、ビルド成果物）
    - OS・エディタ固有のファイル（`.DS_Store` など）
    - パスワードやAPIキーなどの機密情報
    - サイズの大きいバイナリファイル

## コマンドチートシート

### セットアップ

| コマンド | 説明 |
|---|---|
| `git init` | 新しいリポジトリを作成 |
| `git clone URL` | リモートリポジトリをコピー |
| `git config --global user.name "名前"` | 名前を設定 |
| `git config --global user.email "メール"` | メールアドレスを設定 |

### 日常操作

| コマンド | 説明 |
|---|---|
| `git status` | 現在の状態を確認 |
| `git add ファイル名` | ステージングに追加 |
| `git add .` | 全ての変更をステージングに追加 |
| `git commit -m "メッセージ"` | 変更を記録 |
| `git push` | リモートに送る |
| `git pull` | リモートから取得 |

### 確認・比較

| コマンド | 説明 |
|---|---|
| `git log` | commit履歴を見る |
| `git log --oneline` | commit履歴を1行ずつ見る |
| `git diff` | 未ステージングの変更を見る |
| `git diff --staged` | ステージング済みの変更を見る |

### やり直し

| コマンド | 説明 |
|---|---|
| `git restore ファイル名` | ファイルの変更を取り消す |
| `git restore --staged ファイル名` | ステージングを取り消す |
| `git revert HEAD` | 直前のcommitを打ち消す |

## よくある質問

??? question "commitメッセージは何を書けばいい？"
    「何をしたか」が分かるように簡潔に書きましょう。

    **良い例：**

    - `monitoring設定ファイルを追加`
    - `タイムアウト値を30秒から60秒に変更`
    - `不要なログ出力を削除`

    **悪い例：**

    - `更新`
    - `修正`
    - `あああ`

??? question "addとcommitを一緒にできない？"
    追跡済みファイルの変更に限り、`git commit -am "メッセージ"` で `add` と `commit` をまとめられます。
    ただし新規ファイルは対象外なので、最初は `add` → `commit` を分けて実行するのがおすすめです。

??? question "pushしたあとに間違いに気づいた。どうすればいい？"
    `git revert HEAD` で打ち消しcommitを作り、再度pushするのが安全です。
    pushした履歴を無理に書き換えるのは避けましょう（特にチームで使う場合）。

??? question "よく分からないエラーが出た"
    まず `git status` で現在の状態を確認してください。
    そのうえで、**エラーメッセージをそのままCopilotに貼り付けて聞く**のが最も早い解決法です。

ここまでの内容で、個人でのバージョン管理は十分にできるようになっているはずです。

さらに学びたい場合は、以下のトピックに進むとよいでしょう：
